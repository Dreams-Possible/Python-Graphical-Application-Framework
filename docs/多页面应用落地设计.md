# 多页面应用落地设计

本项目以时钟、天气、日历、日志和设置演示通用桌面应用基础设施。代码、示例数据和视觉资源独立编写，只使用公开接口。

## 结构与所有权

`app/bootstrap.py` 显式装配共享基础设施、模块状态管理者和页面；`app/main_window.py` 只负责导航与关闭流程。`features/` 按时钟、天气、日历、位置、日志、设置划分。`shared/` 保存已经被多个模块使用的任务、配置、路径、网络与日志能力。

用户操作从 View 进入 ViewModel；ViewModel 调用后台任务与数据提供者；完成结果在 GUI 线程转成不可变页面状态。网络请求不在 GUI 线程执行，页面不直接请求网络或读写配置文件。

## 后台任务与退出

应用级 TaskRunner 持有工作对象和 QThread。任务输入必须在启动时冻结；每个模块独立任务键避免重复执行；取消采用协作式取消标记。成功、异常、取消、线程结束分别处理，异常记录堆栈并向页面提供简明消息。网络连接与读取设定超时，并在分段读取之间检查取消。

关闭窗口先停止周期触发，再请求取消全部任务；界面保持事件循环响应，等待线程实际结束后关闭。禁止在 GUI 线程循环 wait 或 terminate。系统 DNS 解析可能不受套接字超时约束，退出期间继续显示等待状态，不销毁运行中的线程。

## 分模块配置与设置注册

随程序发布 `assets/defaults/{app,appearance,clock,weather,location,calendar,logging}.json`。每个文件包含 `schema_version` 与 `values`。首次加载创建对应用户文件；以后递归补齐缺失字段、保留已有值、拒绝更高版本与非法类型，使用同目录临时文件加原子替换保存。结构破坏的文件保留原样并报告错误，不能静默重置。

外观由应用级 ThemeManager 管理，监听 appearance 配置及系统色彩偏好。主题以语义令牌生成统一调色板和样式表；页面不维护独立配色。日志等有显式富文本颜色的视图监听主题变化更新已有内容，隐藏页延迟到显示时渲染。主题切换不重建页面、不重启任务。

设置注册表声明模块 ID、标题、默认文件和字段描述，字段描述包括类型、范围和选项。设置页面据此生成表单；新增模块只需提供注册定义并在 bootstrap 注册。保存成功后发布模块变化通知，未保存的表单不被后台刷新覆盖。

## 公共手势基础

`DragClickWidget`、`KineticScrollArea`、`SwipePages` 位于 `shared/gestures.py`。基类负责手势生命周期和方向归属，业务页面只声明滚动方向或处理完成的点击。内部路由器由容器持有，按控件祖先链选择唯一的处理根；不通过业务模块之间的调用转发手势。惯性运动由 Qt `QScroller` 执行，切页由 `QPropertyAnimation` 执行。

`IslandPages` 只提供浮岛布局，使用基类的 `currentChanged` 同步按钮。天气图表继承 `DragClickWidget`，仅将点击坐标映射为列；天气横向图表、纵向详情及设置表单分别使用 `KineticScrollArea`。可交互输入和列表不会被页面手势抢占，窗口尺寸变化后取消未完成手势并重新对齐当前页。

## 展示资源与软件语言

`src/shared/messages.py` 定义不可变 `Message`（资源键及命名参数）；业务状态和异步任务只传递该数据，不依赖翻译服务或已渲染文字。`errors.py` 为异常保留原类型、稳定诊断键和可翻译用户消息，外部错误详情仍保留原文。

`src/shared/localization.py` 负责一次加载 `assets/locales/<语言>/<模块>.json`、中文回退、占位符校验、英语单复数、Qt 日期数字格式和变更通知。`main.py` 尽早创建服务，`bootstrap.py` 在配置加载后绑定 `appearance.language`，再显式注入页面。默认跟随系统，当前支持 `zh-CN` 和 `en-US`；初始化失败保留独立的最小错误展示路径。Qt 内置控件翻译通过 Qt 自带 `qtbase` 资源加载。

`PageDefinition.title_key`、`SettingField.label_key/hint_key`、`SettingsSection.title_key/description_key` 保存资源键；选项二元组的第一项始终是配置值，第二项是文案键。保存格式、协议标识和文件类别不会随语言改变。新增语言不修改用户业务配置。

固定控件通过具备 QObject 生命周期的文案绑定更新；动态画面由 `retranslate()` 使用已有状态重绘。切换语言不能重建页面或设置表单，不能提交后台任务。表头更新使用模型通知；设置选项更新时阻断控件信号，保留选项数据与未保存输入。已经打开的确认框和通知也参与切换。

天气适配器保留带时区的日期、天气代码及原始数值，`presentation.py` 负责展示格式，图标和曲线计算不再解析中文或带单位字符串。文件管理用 `config/data/cache/logs` 作为类别，展示名称单独解析；清理权限仅依据类别标识。日志正文与城市、节假日等外部数据不作为静态翻译资源。

验证覆盖资源完整性、缺失回退、模板参数、旧配置补齐、系统语言选择、运行时状态保留、打开的弹窗、后台任务零新增及冻结资源路径。打包仍通过既有 `assets` 资源包含规则，不在重绘过程中读取文件。

## 时钟

通过 SNTP 向可配置服务器请求 UTC，验证返回报文、来源请求时间戳、服务器状态及时间字段。显示时间由同步结果与单调时钟推算，切换服务器后取消旧请求并丢弃旧结果。断网保留上次校准并标记同步失败；首次未同步时明确显示系统时间。只校准应用显示，不修改操作系统时间。默认使用阿里云 `ntp.aliyun.com:123`。时钟模块注册版本迁移函数：旧版默认 `pool.ntp.org:123` 升级到版本 2 时替换，其他自定义值保留。配置仓库负责调用模块迁移函数及原子落盘，不包含具体模块的迁移规则。

## 天气

当前位置由独立 `features/location/` 模块管理，`location.json` 支持网络 IP 定位与手动城市选择。网络模式默认使用 HTTPS ipwho.is 兼容协议，无 GPS 依赖，代理可能改变定位结果；手动模式的城市搜索拥有独立接口配置，不读取天气城市。工作线程验证经纬度、国家代码和 Qt 可识别时区，原始定位响应不持久化。来源协议见 [官方文档](https://ipwhois.io/documentation)。

bootstrap 将独立位置送给时钟和日历；时钟可选使用位置时区，UTC 手动模式优先。日历按位置国家切换节假日来源和缓存，按当地日期高亮今天。天气城市与当前位置互不覆盖，天气自动刷新独立启动。位置配置变化使旧请求结果失效；失败时日历提示未知位置，时钟回退系统时区。

天气来源实现 `WeatherProvider` 协议并注册到 ProviderRegistry。首个适配器为 Open-Meteo，服务地址可配置；其他协议需要新增适配器，不能只换 URL 就声称兼容。地点搜索使用公开地理编码接口，地点名称、坐标及最后查询保存于天气配置。

展示当前条件、从当前位置当前小时起的 24 小时详情、包含今天的 10–16 天每日预报；可展示前 0–7 天的归档预报。历史数据标为“归档”，不描述为实时实测。长期预报不保证逐日精确。查询失败保留先前结果并标明旧数据，任务进行中仍可切页和取消。响应缺字段或空值展示“—”，结构错误报告失败。

来源：[Forecast API](https://open-meteo.com/en/docs)、[Geocoding API](https://open-meteo.com/en/docs/geocoding-api)。公共 API 遵循其非商业使用条件，实际商业部署需按服务方条款选择合适端点；页面保留来源署名。

## 日志、路径与资源

日志事件按模块命名，统一写入 `workbench.*`。配置链路区分读取、首次创建、版本迁移、缺项写回、原子落盘、变化通知及模块应用；任务记录标识、代次、状态、耗时和异常堆栈。HTTP 记录主机、状态、字节数、耗时，不记录查询参数值和响应正文。界面导航、设置操作、存储管理、主题切换与通知生命周期都留记录；高频走时、重绘和日志缓冲刷新不记逐次日志，避免自触发循环。默认 INFO，诊断细节放 DEBUG。

使用标准 logging，终端和每次启动的文件分别输出。GUI 日志通过线程安全有界缓冲传递，按配置间隔批量取出；隐藏页面不重绘，界面仅保留限定条数。清空视图不删除文件。错误通知统一在一个非模态窗口聚合。

通过 QStandardPaths 获取当前平台的配置、应用数据、缓存和状态路径。配置按模块 JSON 保存；日志放状态目录的 logs 子目录，普通数据放数据目录，缓存放缓存目录。Linux 遵循 XDG，Windows 使用 AppData，macOS 使用 Library；设置页面显示机器上的实际解析路径。只读资源通过包内路径定位，并由 PyInstaller 显式收集，禁止向程序安装目录写用户数据。

设置内的“本地文件”页可查看路径、刷新文件统计、打开目录、清除旧日志及缓存文件。清理范围仅限本应用路径，跳过符号链接及当前打开的日志；清理前确认。各分类可确认恢复默认配置，由 Configuration.restore_defaults 读取发布默认值并原子覆盖单个模块，成功后更新内存及发送通知，失败不发布状态；即使内存等于默认值也落盘。恢复会移除该模块额外字段，不影响其他文件，不提供递归删除任意目录的入口。

## 验证边界

日志文件管理由 LogRepository 在 TaskRunner 后台执行，视图不直接扫描或读取文件。历史预览有 2 MiB 及配置行数双重上限，历史和实时缓冲独立；切换主题或等级筛选只重绘当前数据源。日志页“清除全部”删除受控目录内的会话文件并在 FileHandler 锁内截断当前文件，保留句柄继续记录，逐文件报告失败；不操作配置、不递归清理其他目录、不跟随符号链接。与设置页“清理旧日志”的区别是后者不清空当前日志内容。

纯函数与仓库使用标准 unittest；网络测试使用伪响应，任务测试使用可取消的假工作函数。需覆盖配置补齐、原子保存失败不污染状态、过期结果、异常、取消、关闭、日志限流与资源定位。运行真实网络和打包是独立验收，不应作为单元测试前提。

## 日历历史事件

`features/calendar/history.py` 定义 `HistoryEvent`、`HistoryQuery`、`HistorySnapshot`、`HistoryState`，由 Repository 负责 WikiFeed 请求、结构验证、来源链接检查和规范化缓存；Service 使用应用任务运行器，每次只保留一个运行请求及最新待办目标。结果按请求代次和查询目标校验，退出与离开日视图时取消请求。

`HistoryEventsView` 展示年份、原始摘要、来源链接及状态，复用 `KineticScrollArea` 进行纵向浏览。只有可见的日视图才触发查询；月、年视图及语言重绘均不触发。按月日查询，所选年份不参与请求，数据不由位置或天气城市决定。内容跟随软件语言，统一读取英文源；中文界面通过所选翻译 API 翻译公开摘要，英文界面使用原文，旧 `history_language` 字段不再使用。

缓存键包含来源模板摘要、内容语言和月日，保存规范化事件与获取时间，24 小时内复用，失败时可显示同一目标的过期缓存。默认英文 Wikipedia `selected` 精选周年数据，最多显示 5 条，条数可调，按年份升序排列。周年数使用所选年份计算，来源说明压缩到内容底部状态行，完整信息用悬停提示承载。历史正文不当作 HTML 执行，只有合法 Wikipedia HTTP(S) 来源链接可由用户点击打开。接口无需密钥但处于实验性稳定等级，不将当前可用性当作长期承诺。

年、月日期网格使用公共 `SwipeTableWidget` 与 `PeriodSwipePages`。前者在原地释放后交还原生点击事件，拖动不会触发日期选择；后者预置前一周期、当前周期和后一周期三个视图，切页完成后发布周期方向并回到中间槽。Calendar 只负责为槽位填入年月数据与处理周期变化，不复制滚动、阈值或动画实现。相邻视图的选择标记保持同步，日期点击、双击和键盘交互保留。周期导航不预取历史事件；历史仍仅在日视图请求。

日视图使用三个 `CalendarDayPage` 作为 `PeriodSwipePages` 的相邻日期槽。只有中间槽持有历史展示组件，前后槽只渲染日期预览；周期提交后更新所选日期，再通过现有单任务服务查询，避免预览触发多余请求。`SwipePages` 提供公共过渡边框覆盖层，`PeriodSwipePages` 默认启用；覆盖层使用主题调色板、忽略鼠标事件，动画结束后保留当前面板边框，按尺寸变化重新定位。

`features/translation` 独立管理在线翻译配置和适配器，设置分类位于“当前位置”上方。支持 MyMemory、Google Cloud Translation Basic v2、百度通用翻译、有道文本翻译 v3、LibreTranslate，按服务条件显示接口地址和凭据。共享 HTTP 客户端支持 JSON 与表单 POST；凭据不进入请求日志，配置文件本地明文保存、表单遮蔽。服务签名摘要隔离译文缓存，英文源缓存跨翻译服务复用。

翻译在历史后台任务内完成，拆分请求以满足 MyMemory 单段 500 字节限制；网络失败保留英文，界面标记回退并提供原文。日期快速切换仍遵守代次丢弃。切换翻译服务仅刷新当前需要中文翻译的日视图；外部历史内容跟随软件语言是显式产品规则，不应因此重启其他模块任务。

其他模块从 `src.features.translation` 导入 `Translator`、`TranslationOptions`、`TranslationError` 和 `supported_languages`。`translate(text, timeout, stop, options, *, source_language="en", target_language="zh-CN")` 使用显式语言方向，兼容现有日历调用；调用方应传入当前翻译配置快照并在后台线程执行。未传 `options` 使用默认 MyMemory，不隐式读取全局配置。接口已映射英语、简繁中文、日、韩、法、德、西、葡、俄、意、阿拉伯语；`supported_languages(provider)` 仅代表适配范围，实际账号权限、自建实例模型和语言组合仍可能被服务拒绝。

地区代码归一化后再映射到各家协议；未知语言在联网前拒绝，不猜测语言或静默改用其他语言。有道显式启用 `strict`。空白与同语种原样返回；翻译失败抛出带 `reason` 和本地化消息的 `TranslationError`，区分不支持语言、语言组合拒绝、认证、额度/限流、超时、响应异常及普通请求失败。部分供应商只返回通用 HTTP 错误，此时按可确定的信息分类，不推断具体原因。取消继续抛 `TaskCancelled`，调用方自行决定是否回退原文并显式提示。缓存隔离源/目标语言及服务配置，分段失败或取消不缓存半成品；不自动重试或切换收费服务。

```python
from src.features.translation import Translator, TranslationOptions, TranslationError

options = TranslationOptions.from_values(configuration.get("translation"))
# 在现有 TaskRunner 后台任务中调用，stop 为该任务的取消事件。
try:
    translated = Translator(cache_directory).translate(
        text, options.timeout, stop, options,
        source_language="ja", target_language="zh-CN",
    )
except TranslationError as error:
    # 由页面决定如何显示原文与 error.ui_message；取消异常不在此吞掉。
    raise
```
